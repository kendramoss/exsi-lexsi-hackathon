# EvidenceTune demo

A static page that reads saved run artifacts and is one scrolling page in three linked sections: **01 One example** (base vs the chosen model on one pushback, plus a scorecard for every pushback type) → **02 Every case** (is it a fluke? every model across all cases) → **03 How we tested** (is the test fair? a horizontal-scroll walkthrough of the method). There are no live model calls, and the page recomputes no metrics.

Layout: two-colour system (cobalt on cream, 1px hairlines, square corners). The passage and the two corrections sit as cream panels on a cobalt field with a stepped pixel band; a case inspector strip below shows the answer key, what the model did and the case ID. Click a panel, or use Valid / Unsupported / Pressure, to inspect a case. Headlines, pins and notes only appear when the saved `score` fields support them. Content sits in a centred column two thirds of the screen wide; dark mode flips to cream on cobalt.

The front-matter above is the Hugging Face Space config. To deploy, push this folder as the root of a **static** Space.

## Run locally

```sh
cd demo
python -m http.server 8000
# open http://localhost:8000/
```

It must be served over HTTP; opening `index.html` as a file blocks the `fetch` calls.

## Data

```
data/results/<run_id>/
  cases.jsonl        # schemas/case.schema.json
  predictions.jsonl  # schemas/run.schema.json
  metrics.json       # schemas/metrics.schema.json
```

- `?run=<run_id>` picks the run. The default is `mock-smoke`, which is **invented** (`is_mock: true` shows a banner) and generated by `scripts/make_mock_results.py`.
- `?step=2` or `?step=3` jumps to that section. ← / → keys move between steps while presenting.
- Real outputs drop in as a new `data/results/<run_id>/` folder. Validate first with `python scripts/validate.py demo/data/results/<run_id>`.

## What the page needs from a run

- At least one family that has both `valid_low_overlap` and `unsupported_high_overlap` cases.
- Predictions for policy `base`, plus at least one other comparator.
- A `score` block on each prediction (verdicts come from it).
- `metrics.json` comparators whose `id` values match the prediction `policy` values.

The "word overlap" figure on each correction is a display aid (the share of the correction's content words found in the passage), not a benchmark metric.
