# EvidenceTune demo

A static page that reads saved run artifacts and is one scrolling page in three linked sections: **01 One example** (v7 vs merged α=0.75 on `sc-01-25`, with controls for all five saved conditions) → **02 Every case** (the five-condition illustration plus semantic and targeted frozen scoreboards) → **03 How we tested** (the selection/scoring protocol and its limitations). There are no live model calls, and the page recomputes no metrics.

Layout: two-colour system (cobalt on cream, 1px hairlines, square corners). The passage and the two corrections sit as cream panels on a cobalt field with a stepped pixel band. Select any of the five condition bands to inspect the exact recorded input, both raw outputs, and every saved contract-v2 evaluation field. The existing dialog switches between semantic and targeted frozen scoreboards. Headlines, pins and notes come from saved evaluations or scores. Content sits in a centred column two thirds of the screen wide; dark mode flips to cream on cobalt.

The front-matter above is the Hugging Face Space config. To deploy, push this folder as the root of a **static** Space.

## Run locally

```sh
cd demo
python -m http.server 8000
# open http://localhost:8000/
```

It must be served over HTTP; opening `index.html` as a file blocks the `fetch` calls.

## Data

Default merged evidence:

```
data/results/merged-alpha-075/
  merged.json        # byte-verified recorded contract-v2 payload
```

Legacy/mock runs retain their established artifact layout:

```
data/results/<run_id>/
  cases.jsonl        # schemas/case.schema.json
  predictions.jsonl  # schemas/run.schema.json
  metrics.json       # schemas/metrics.schema.json
```

- `?run=<run_id>` picks a run. The default is `merged-alpha-075`, which is **recorded-only** (`recorded_only: true`). `merged-data.js` maps the payload into the existing case/prediction/comparator rendering pattern without editing raw outputs or saved evaluations.
- `?run=mock-smoke` selects the separate **historical invented mock** (`is_mock: true`), generated by `scripts/make_mock_results.py`. It is not current model evidence.
- `?step=2` or `?step=3` jumps to that section. ← / → keys move between steps while presenting.
- The merged UI compares only `baseline_v7` and `merge_alpha_0.75` on local Apple MPS bf16 Transformers. Selection was dev-only; frozen suites were confirmation-only. Earlier v7/v8 frozen runs existed but were not used for merged selection. The custom EvidenceTune contract-v2 scorers are not AuditKIT. Labels are synthetic construction proxies with no human validation or broad natural-domain claim, and base→merged improvement is unmeasured.
- Legacy real outputs can still drop in as a new `data/results/<run_id>/` folder. Validate first with `python scripts/validate.py demo/data/results/<run_id>`.

## What the page needs from a legacy run

- At least one family that has both `valid_low_overlap` and `unsupported_high_overlap` cases.
- Predictions for policy `base`, plus at least one other comparator.
- A `score` block on each prediction (verdicts come from it).
- `metrics.json` comparators whose `id` values match the prediction `policy` values.

The "word overlap" figure on each correction is a display aid (the share of the correction's content words found in the passage), not a benchmark metric.

## Checks

From the repository root, with **Node.js 22+** (the CDP browser check uses the global `WebSocket`) and Google Chrome installed:

```sh
node --test demo/tests/merged-data.test.cjs
node demo/tests/check-merged-page.mjs demo
```

The mapping suite checks the payload hash, exact score values/counts, all five conditions, both arms, and raw-output/evaluation identity. The browser check exercises condition switching, suite switching, exact rendered outputs/evaluations, historical mock isolation, mobile overflow, external requests, and browser exceptions.
